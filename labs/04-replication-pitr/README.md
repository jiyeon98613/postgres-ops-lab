# 04. 스트리밍 복제와 특정 시점 복구

## 목적

replica를 중단한 동안 primary에 추가된 데이터가 재시작 후 반영되는지 확인했습니다. 이어서 물리 백업과 WAL 아카이브를 사용해, 테이블을 삭제하기 직전 시점으로 복구했습니다.

정기 백업을 복원한 PostgreSQL 18.6을 실습 primary로 사용했습니다. primary, replica, 복구 인스턴스는 같은 Linux 서버에서 각각 다른 데이터 디렉터리와 Unix socket으로 실행했습니다.

## 실행한 명령

앞의 복구·성능·권한 실습을 마친 작업 디렉터리에서 실행했습니다. 이 명령은 실습 primary의 테이블을 삭제하므로 1~4번 실습 중 마지막에 실행합니다.

```bash
python scripts/physical.py \
  --workspace "$LAB_WORKSPACE" \
  --pg-bin /usr/lib/postgresql/18/bin
```

[실습 스크립트](../../scripts/physical.py)의 스트리밍 복제 순서는 다음과 같습니다.

1. 실습 primary에 전용 복제 계정을 만들고 `pg_basebackup -X stream -c fast -R -C -S pgops_replica`로 replica를 구성했습니다.
2. replica가 recovery 상태이고 초기 검증 행을 받은 것을 확인한 뒤 종료했습니다.
3. primary의 검증 테이블에 1,000행을 추가하고, replica를 다시 시작했습니다.
4. `pg_last_wal_replay_lsn()`이 목표 WAL 위치에 도달했는지 확인하고 검증 행과 백업의 전체 테이블을 대조했습니다.
5. replica를 종료한 뒤 실습용 복제 슬롯을 제거했습니다.

PITR은 같은 스크립트에서 이어서 실행했습니다.

1. 실습 primary의 WAL 아카이브를 켜고 `pg_basebackup`으로 별도의 물리 백업을 만들었습니다.
2. 백업 이후 검증 행을 추가하고 복구 목표 시각을 기록했습니다.
3. `staging.change_items`를 삭제하고 목표 시각 이후의 검증 행을 추가했습니다.
4. 필요한 WAL이 보관됐는지 확인한 뒤, 복구 인스턴스에 `recovery.signal`, `restore_command`, `recovery_target_time`을 설정했습니다.
5. 목표 시점에서 WAL 재생이 일시 정지했는지 확인하고 `pg_ctl promote`로 복구를 완료했습니다.
6. 삭제된 테이블, 목표 이전·이후의 검증 행, 전체 테이블의 값과 복구 후 쓰기 가능 여부를 확인했습니다.

원본 백업은 보존했습니다. 실습 primary는 테이블 삭제 이후 상태이고, 복구된 데이터는 별도 인스턴스의 디렉터리에 남겼습니다. 실습이 끝난 뒤에는 세 인스턴스를 모두 종료했습니다.

## 막혔던 점

일회용 데이터로 검증하는 과정에서, 목표 시점에 일시 정지한 복구 DB의 테이블을 조회하다가 `55P03` 잠금 오류가 발생했습니다. 일시 정지 상태에서는 WAL 재생과 관련된 잠금 때문에 조회가 막힐 수 있었습니다.

목표 시점 도달 확인과 테이블 검증을 분리했습니다. 먼저 WAL 재생이 목표에서 정지했는지 확인하고, 명시적으로 복구를 완료한 뒤 테이블을 조회하도록 순서를 바꿨습니다. 수정 후 일회용 데이터 검사와 실제 백업 검증을 모두 통과했습니다.

## 배운 점

replica가 실행 중이라는 사실에 더해, 어느 WAL 위치까지 반영했는지와 실제 데이터가 같은지 확인해야 했습니다. 이번에는 목표 WAL 위치, 검증 행 수, 전체 테이블 값까지 대조했습니다.

PITR에서는 삭제된 테이블이 돌아온 것과 함께 복구 시점도 검증해야 했습니다. 물리 백업 이후에 추가한 행이 살아 있고 목표 시각 이후의 행은 없는지 확인해, 원하는 구간까지 WAL이 재생됐는지 판단했습니다.

운영 DB는 확인 당시 `archive_mode=off`였고, WAL 아카이브와 복제 설정은 실습 인스턴스에만 적용했습니다. 운영에 적용하려면 별도의 설정과 검증이 필요합니다. 이번 구성은 같은 서버의 프로세스들로 실습했으므로 물리 서버 장애에 대한 내성을 확인한 결과도 아닙니다.
